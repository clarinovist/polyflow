# Barter PostgreSQL integration (opt-in only)

Never use the application's `DATABASE_URL`. Do not run `npm run dev` or migration deploy against a tenant/default database for this suite.

The suite reads **only** `BARTER_TEST_DATABASE_URL` and `BARTER_TEST_DATABASE_URL_2`. Both are required for an enabled run. URLs must use PostgreSQL, `127.0.0.1`, an explicit port, and database names `polyflow_barter_test` / `polyflow_barter_test_2`. Arbitrary URL options (including host overrides) are rejected. Before truncating fixture tables it checks `current_database()`, recovery status, and the dedicated marker table. Absence of the first variable skips the integration suite; a skip is **not** evidence of concurrency correctness.

## Disposable setup

Create your own PostgreSQL 16 container (do not reuse another session's container):

```sh
docker run -d --name barter-disposable \
  -e POSTGRES_PASSWORD=disposable_only -e POSTGRES_DB=polyflow_barter_test \
  -p 127.0.0.1::5432 postgres:16-alpine
docker port barter-disposable
# Wait for pg_isready, then create the second database with docker exec psql.
```

Apply a **pre-barter baseline** schema generated by `prisma@5.22.0 migrate diff --from-empty --to-schema-datamodel <pre-barter-schema.prisma> --script`, using `docker exec -i ... psql -v ON_ERROR_STOP=1 -U postgres -d <explicit-test-db>`.

Then apply, separately and in order:

1. `prisma/migrations/20260909_barter_reference_type/migration.sql`
2. `prisma/migrations/20260909_barter_settlement/migration.sql`
3. `prisma/migrations/20260910_barter_query_indexes/migration.sql`

For compatibility validation, insert a legacy Payment before those migrations in one database; assert its amount/method/status are unchanged and both new barter fields are NULL afterward. The other database exercises an empty baseline. `prisma db push` alone is insufficient: it omits the SQL constraints/triggers.

Only inside both disposable databases, create the safety marker:

```sql
CREATE TABLE "BarterDisposableMarker" (purpose text PRIMARY KEY);
INSERT INTO "BarterDisposableMarker" VALUES ('barter-integration-disposable');
```

Run, substituting the container's published localhost port:

```sh
BARTER_TEST_DATABASE_URL='postgresql://postgres:disposable_only@127.0.0.1:<port>/polyflow_barter_test' \
BARTER_TEST_DATABASE_URL_2='postgresql://postgres:disposable_only@127.0.0.1:<port>/polyflow_barter_test_2' \
npx vitest run src/services/finance/__tests__/barter-settlement-postgres.test.ts
```

Tests use real transaction, sequence, invoice, journal, audit and partner services. Only account-role mapping and tenant payment-bank settings use synthetic fixture values; no DB writes/locks/journals are mocked. Row-lock tests assert `pg_blocking_pids`, not just elapsed time. A failing database audit trigger proves late create/void rollback. The raw test client deliberately has no global status-audit extension: assertions concern the critical transactional audit, not the known outer-client auto-audit limitation.

The suite truncates fixture finance tables and replaces synthetic fixtures between tests. Do not point it at a database containing valuable data even if it has the allowed name. Remove only your disposable container after verification.
